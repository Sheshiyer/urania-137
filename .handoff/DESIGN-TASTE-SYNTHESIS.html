IV. 3D WebGL Interactive Direction

The landing shifts from a scroll-driven 2D page to an interactive 3D WebGL scene with Urania's sacred geometry narrative rendered as an explorable space. Clickable room/engine components overlay the 3D canvas as HTML/CSS elements.

The Concept

A procedural Three.js scene generates Urania's celestial instrument at runtime — no external 3D models. The constellation graph becomes a navigable 3D space: orbital rings trace the 7 rooms, astrolabe plates rotate at the center, flower-of-life sacred geometry pulses as ambient structure, and beaded lattice connects the engine nodes.

The viewer orbits this space freely (OrbitControls). Clickable HTML/CSS components — room cards, engine panels, workflow indicators — are positioned in 3D space using CSS3DRenderer or projected screen coordinates, creating a hybrid WebGL + DOM interface.

Architecture: The Split Render

WebGL Canvas Three.js procedural geometry — orbital rings, astrolabe, sacred geometry, starfield, nebulae, particle systems
HTML Overlay Room cards, engine panels, workflow roster, navigation, copy — positioned via CSS3DRenderer or screen projection
Motion Layer GSAP scroll-driven transitions between views, explode/reassemble animations, camera path sequences
Data Layer selemeneNodes.ts → landingData.ts → landingCopy.ts → 3D scene graph (unchanged data chain)

Interaction Model

Camera + Navigation

  • Orbit — Free orbital camera via OrbitControls (damped, bounded). Default view: slightly above, looking down at the constellation plane.
  • Focus — Click a room node to fly the camera toward it, revealing its engine/workflow children in an exploded view. GSAP-driven camera path with out-expo easing.
  • Explode/Reassemble — Room detail view spreads child nodes outward; returning to overview reassembles the constellation. Inspired by the Temple of Heaven reference.
  • Scroll Integration — On mobile or when the user scrolls rather than orbits, the camera follows a predefined path through the scene — a guided tour through rooms in sequence.

Clickable Components (HTML Overlay)

  • Room Cards — Liquid-glass panels that appear when a room node is focused. Show room label, epithet, engine/workflow counts, and a "learn more" CTA.
  • Engine Panels — Compact cards showing engine name, substrate tag (Rust/TypeScript), and one-line description. Visible in room detail view.
  • Hero Copy — Fixed overlay for the landing headline, brand line, and primary CTA. Fades as the user begins to orbit.
  • Navigation HUD — Minimal fixed nav with room pills that double as camera-target buttons.
  • Invitation Panel — The threshold invitation as a centered glass panel at the "exit" of the guided tour.

Mobile Fallback

Mobile devices that cannot sustain 60fps WebGL get a scroll-driven 2D experience using the existing motion system (GSAP + IntersectionObserver). The ConstellationGraph SVG replaces the 3D scene. Feature detection via WebGLRenderingContext availability + device memory/GPU tier.

V. Unified Design Direction

The Thesis

Urania 137's landing is a celestial instrument you can explore — not a page you scroll through. The constellation graph (7 rooms, 13 engines, 6 workflows) becomes a navigable 3D space where every node is a real capability. Clickable glass panels overlay the procedural geometry, bridging the abstract beauty of the sacred geometry with the concrete utility of the reading field.

The visitor's first experience is witnessing the instrument assemble itself — procedural geometry building from void to constellation — before they can orbit it, focus on rooms, and eventually cross the threshold into the protected app.

Key Decisions

  • Three.js + CSS3DRenderer for the hybrid WebGL + DOM approach. R3F (React Three Fiber) for React integration.
  • GSAP ScrollTrigger for camera path sequences and scroll-to-orbit handoff on desktop.
  • Procedural everything — no external models. All geometry generated from code: torus knots, parametric curves, instanced meshes.
  • Data-driven scene graph — room positions, colors, and engine counts derived from selemeneNodes.ts. Same data chain, 3D output.
  • Existing motion token — cubic-bezier(0.19, 1, 0.22, 1) drives all GSAP camera animations. One easing for the whole instrument.
  • Progressive enhancement — 3D for capable devices, scroll-driven SVG fallback for mobile/low-end. Bundle budget: Three.js core ~150KB gzipped, offset by removing the Golden Portal template weight.
  • Assembly entrance — initial load plays a 3-4 second build sequence: void → starfield → orbital rings → room nodes → constellation lines → astrolabe core. Then hero copy fades in.

Visual Priorities

  1. Gold wireframe structure on void — the primary visual language. No solid fills, no gradients. Gold outlines define every geometric form.
  2. Room-color nebula accents — volumetric glow in each room's accent color creates spatial depth and identity without overwhelming the gold wireframe.
  3. Liquid-glass HTML panels — backdrop-blur glass cards for all readable content. The existing liquid-glass CSS class, elevated to 3D space.
  4. Sacred geometry as ambient structure — flower-of-life, metatron's cube as subtle transparent planes. Always present, never the focus.
  5. Cinzel headlines, Satoshi body — the type stack is unchanged. Engraved serif authority for titles, clean sans for utility.

What Carries Forward from the Approved Plan

  • All 5 routes preserved: /, /instrument, /lenses, /principles, /enter
  • Data chain untouched: selemeneNodes → landingData → landingCopy → components
  • Shell (nav + footer) liquid-glass treatment
  • 14 easter eggs from the plan (adapted to 3D context)
  • GlyphIcon component port from app
  • RevealCounter, AmbientGlow, SectionSeparator primitives
  • Bundle budget discipline (Three.js replaces Golden Portal template weight)
  • Orphaned landing.css deletion
  • All copy, counts, and room data from landingCopy.ts

What Changes

  • HomePage hero: video background → interactive Three.js scene
  • Rooms overview: card grid → explorable 3D constellation with glass overlays
  • Engine roster: flat grid → engine nodes in room detail view
  • Navigation model: scroll-driven → orbit + focus + scroll fallback
  • New dependency: three + @react-three/fiber + @react-three/drei
  • ConstellationField (planned 2D SVG) → ConstellationScene (3D procedural)
